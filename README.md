## 🇮🇷 نسخه فارسی (Persian Version)

بزرگ‌ترین چالش بیشتر مردم در کار با مدل‌های زبانی بزرگ (LLM) مانند GPT-4o، Claude 3.5 و Gemini این است که ابزارها را مثل موتور جستجو فرض می‌کنند. برای گرفتن دقیق‌ترین و باکیفیت‌ترین پاسخ، شما نیاز به یک ساختار مهندسی‌شده دارید.

**فریم‌ورک STR** یک متدولوژی متن‌باز (Open-Source) است که پرامپت‌نویسی را به ۳ رکن اساسی تقسیم می‌کند:
۱. **Stage (نقش/زمینه):** تعیین کیستی و لحن هوش مصنوعی.
۲. **Task (وظیفه):** خروجی دقیق و اصلی مورد نیاز.
۳. **Rules (قوانین و محدودیت‌ها):** مرزها، فرمت خروجی و خطوط قرمز.

👉 **[مشاهده وب‌سایت و داکیومنت زنده پروژه](https://AmirMotefaker.github.io/STR-Prompt-Framework)**

### 💡 ارکان فریم‌ورک STR

| رکن | هدف | توضیحات |
| :--- | :--- | :--- |
| **Stage (نقش)** | **زمینه و پرسونای ابزار** | مشخص می‌کند هوش مصنوعی چه کسی است (نقش، سابقه کاری، لحن) و چرا این کار را انجام می‌دهد. |
| **Task (وظیفه)** | **خروجی اصلی و نهایی** | مشخص می‌کند دقیقاً چه خروجی، سند یا کدی باید به شما تحویل داده شود. |
| **Rules (قوانین)** | **محدودیت‌ها و فرمت** | مشخص می‌کند ابزار چطور باید رفتار کند (فرمت مارک‌داون، زبان، لحن، عدم استفاده از کلمات کلیشه‌ای). |

## 🇬🇧 English Version

Stop treating Advanced LLMs like a basic Google search. To get 10x more predictable, accurate, and high-quality outputs, you need a structured architecture. 

The **STR Framework** is an open-source methodology designed to break down prompt engineering into three non-negotiable pillars: **Stage, Task, and Rules**.

👉 **[View the Live Documentation Site Here](https://AmirMotefaker.github.io/STR-Prompt-Framework)**

### 💡 The STR Pillars Explained

| Pillar | Purpose | Description |
| :--- | :--- | :--- |
| **Stage** | **Persona & Context** | Defines *who* the AI is (role, seniority, tone) and *why* it is performing the action. |
| **Task** | **The Core Deliverable** | Defines *what* exact action needs to be taken and the required core output. |
| **Rules** | **Boundaries & Constraints** | Defines *how* the AI must behave (formatting, word limits, anti-hallucination guardrails). |
